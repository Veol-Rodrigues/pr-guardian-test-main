Capabilities

Everything a careful reviewer would do

Nothing here is decorative — each capability maps to a real part of the pipeline that runs on every pull request.

Zero infrastructure

Runs entirely inside GitHub Actions. No servers, no webhooks, no hosting cost.

Automatic triggering

Fires on every opened, synchronize, and reopened pull request event.

Inline, line-level notes

Findings post directly on the exact line they concern, via the Pull Request Review API.

Click-to-commit fixes

Where a concrete correction exists, it arrives as a one-click "Apply suggestion" block.

Graceful at scale

Diffs are chunked cleanly along file boundaries, so a big pull request degrades gracefully instead of failing.

Command Center summary

One root comment ties together a Merge Readiness Score, time saved, and a files-changed overview.

Calm when clean

If nothing stands out, you still get a short, reassuring note — silence would look broken.

Secure by design

Keys live in encrypted GitHub Secrets and never touch your codebase.

Free to run

Uses GitHub Actions' free tier and the Gemini API's free tier.

Our philosophy

Calm Engineering

Most automated review tools are built to alarm you — red banners, "CRITICAL" labels, a wall of warnings that all look equally urgent. That's noise, not signal, and it trains people to skim past the tool entirely. PR Guardian reviews the way a good senior engineer does: objective, specific, educational, and unhurried.

No alarmist language

You won't see "critical" or "danger" anywhere in a PR Guardian comment — the category schema doesn't allow it.

A readiness score, not a risk score

92/100 tells you where you stand, without triggering a fight-or-flight response.

Observations, not accusations

Every finding is framed as Security Enhancement, Architectural Observation, or Merge Readiness Suggestion.

How it works

A linear, stateless pipeline

No database, no queue, no persistent process. Each review is triggered by an event, completes in a single job, and posts its result back to the pull request itself.

01

Event ingestion

A pull_request webhook — opened, synchronize, or reopened — spins up an ephemeral GitHub Actions runner.

02

Metadata & diff retrieval

pr_reviewer.py calls the GitHub REST API twice: once for title and head SHA, once for the raw unified diff.

03

Diff segmentation

The diff is split per file, and hunk headers are parsed into the exact new-file lines GitHub will accept a comment against.

04

Intelligent chunking

File blocks are packed under a configurable line threshold, never splitting a single file's diff mid-hunk.

05

AI analysis

Each chunk is sent to Gemini, constrained to a fixed JSON schema of calm, non-alarmist categories.

06

Aggregation & validation

Findings are filtered against the valid-line set; anything that can't be commented on is dropped and logged, never crashing the run.

07

Scoring

The Merge Readiness Score is computed deterministically in Python — never left to model arithmetic that could drift between runs.

08

Delivery

One POST /pulls/{number}/reviews call carries both the inline suggestions and the Command Center summary together.

Getting started

Set up in about five minutes

Two files, one secret, and a permissions check — then every future pull request gets a quiet, thorough review.

01

Get a Gemini API key

Visit Google AI Studio, sign in, and create an API key.

02

Add it as a repository secret

Settings → Secrets and variables → Actions → new secret named GEMINI_API_KEY.

03

Add the two project files

.github/workflows/review.yml and pr_reviewer.py, committed to your main branch.

04

Confirm workflow permissions

Settings → Actions → General → Workflow permissions → Read and write permissions.

05

Open a pull request

Watch the Actions tab — the review typically completes in under a minute.
